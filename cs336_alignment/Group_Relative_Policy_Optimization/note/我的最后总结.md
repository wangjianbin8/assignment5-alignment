# 粗略版本

所以一步完整流程是：

1. 从 train 里抽几道题。
2. 每道题重复 `group_size` 次，让模型分别采样多个回答。
3. 给所有回答打 reward。
4. 同一题内部根据 reward 算 advantage。
5. 把这些回答切成多个 microbatch。
6. 每个 microbatch：
   - 算 token 的 `log π`
   - 算 `-A log π`
   - 聚合成这个 microbatch 的 scalar loss
   - 按 microbatch/full-batch 比例缩放
   - `loss.backward()`，把梯度累积到 `.grad`
7. 所有 microbatch 完成后：
   - clip gradient
   - `optimizer.step()` 更新一次参数
   - `optimizer.zero_grad()`
8. 然后进入下一训练 step。

而 validation 正如你说的：

> 每隔几步，拿 validation 里的题让当前模型重新生成答案，再用 grader 打分，看看 `val reward` 有没有总体上升。

可以把它记成：

```text
一个 training step：
抽题 → 多次回答 → reward → advantage
→ 分 microbatch 算 loss/backward
→ 所有梯度累积完成
→ 更新一次模型

每隔 N 个 training steps：
validation 生成答案 → 打分 → 看模型有没有变强
```

所以 **training 在修改模型，validation 只负责考试，不修改参数。**


# 详细版本
可以，你就把你这版当“主干”，我在这个基础上补充成一份适合记笔记的完整版本。

## GRPO 一步训练的完整流程

1. **从训练集抽题**
   - 从 `train` 里抽若干个 prompt。
   - 如果：
     \[
     \text{rollout\_batch\_size}=256,\quad G=8
     \]
     那其实只抽：
     \[
     256/8=32
     \]
     道题。

2. **每道题生成 `group_size` 个 rollout**
   - 同一道题重复 `G` 次。
   - 用当前 policy：
     \[
     y^{(i,j)}\sim \pi_\theta(y|x^{(i)})
     \]
   - 也就是同一道题采样多个不同回答。

3. **给每个完整回答打 reward**
   - 用 grader 比较 response 和 ground truth。
   - 得到：
     \[
     r_{ij}
     \]
   - 同时可以记录：
     - total reward
     - format reward
     - answer reward

4. **同一题内部计算 advantage**
   - 先算 group mean：
     \[
     \mu_i=\frac1G\sum_j r_{ij}
     \]
   - 再算 group std：
     \[
     \sigma_i=\operatorname{std}(r_{i1},...,r_{iG})
     \]
   - 标准 GRPO：
     \[
     A_{ij}=
     \frac{r_{ij}-\mu_i}{\sigma_i+\epsilon}
     \]
   - 含义：
     - \(A>0\)：这个回答比同组平均好
     - \(A<0\)：比同组平均差

5. **把 prompt + response tokenize**
   得到：
   - `input_ids`
   - `labels`
   - `response_mask`

   `response_mask` 用来保证最后只训练 response token，不训练 prompt/padding。

6. **把整个训练 batch 切成 microbatch**
   - 原因：整个 batch 一次 forward/backward 显存放不下。
   - 但数学上仍然希望等价于一次 full-batch update。

7. **每个 microbatch 做 forward**
   - 模型计算 logits：
     \[
     \text{logits}=f_\theta(\text{input\_ids})
     \]
   - 再算真实 token 的：
     \[
     \log \pi_\theta(y_t|x,y_{<t})
     \]

8. **计算每个 token 的 policy-gradient loss**
   对一条 rollout，它的所有 token 共享同一个 advantage：

   \[
   \ell_{ijt}
   =
   -A_{ij}
   \log\pi_\theta(y_t^{(i,j)}|x^{(i)},y_{<t}^{(i,j)})
   \]

   含义：
   - \(A>0\)：提高这些 token 在对应上下文里的概率
   - \(A<0\)：降低这些 token 的概率

9. **只保留 response token**
   用：
   \[
   m_{ijt}\in\{0,1\}
   \]
   也就是 `response_mask`。

   prompt 和 padding 的位置不进入最终 loss。

10. **一条 sequence 内先平均**
    对一条 rollout：

    \[
    L_{ij}
    =
    \frac{
    \sum_t m_{ijt}\ell_{ijt}
    }{
    \sum_t m_{ijt}
    }
    \]

    也就是：

    > 先对这条 response 的 token loss 求平均。

11. **microbatch 内再对 sequences 平均**
    得到当前 microbatch 的 scalar loss：

    \[
    L_{\text{micro}}
    =
    \frac1M\sum_{i\in\text{micro}}L_i
    \]

12. **修正 gradient accumulation 的权重**
    如果：
    - microbatch 大小 \(M\)
    - full batch 大小 \(N\)

    那么：

    \[
    \tilde L_{\text{micro}}
    =
    L_{\text{micro}}\frac{M}{N}
    \]

    这样所有 microbatch 累积后，才等价于 full-batch loss。

13. **每个 microbatch 都调用 `loss.backward()`**
    - 第一个 microbatch：
      \[
      .grad=g_1
      \]
    - 第二个：
      \[
      .grad=g_1+g_2
      \]
    - 一直到所有 microbatch。

    注意：

    > `backward()` 只是算并累积梯度，还没更新参数。

14. **所有 microbatch 完成后做 gradient clipping**
    计算总梯度范数：

    \[
    \|\nabla_\theta L\|_2
    \]

    如果超过：

    \[
    \text{max\_grad\_norm}
    \]

    就缩小梯度，防止训练不稳定。

15. **`optimizer.step()` 更新一次参数**
    真正执行：

    \[
    \theta
    \leftarrow
    \theta-\alpha\nabla_\theta L
    \]

    由于我们的 loss 里面有负号：

    \[
    -A\log\pi
    \]

    所以等价于对 GRPO objective 做 gradient ascent。

16. **`optimizer.zero_grad()` 清空梯度**
    为下一次 training step 做准备。

17. **进入下一 training step**
    用更新后的 policy 再：
    - 抽新题
    - 采样新 rollout
    - 重新 reward
    - 重新 advantage
    - 再更新一次

## Validation 流程

每隔若干个 training step，比如每 10 步：

1. 从 validation set 取一批题。
2. 用**当前模型**生成答案。
3. 用 grader 打分。
4. 计算：
   - validation total reward
   - validation format reward
   - validation accuracy
   - average response length
5. **不做 backward，不更新参数**。

它只是考试：

\[
\boxed{
\text{validation = 看模型有没有真的变强}
}
\]

---

## Training loop 外围还会做什么

除了主流程，还会定期记录：

- `loss`
- `grad_norm`
- `token_entropy`
- `train reward`
- `train format reward`
- `val reward`
- `val format reward`
- `response length`
- 实际 rollout 文本

这样既能看数字，也能肉眼检查模型有没有学歪。
